🧪 请求样本回放（旧版接受 → 新版拒绝？）

提交多条请求样本，每条包含旧版操作的方法与路径模板、Content-Type 和 JSON 请求体； 后端按相同方法与路径模板在新版查找操作（操作或媒体类型消失视为新版拒绝）， 对两侧请求体分别做 schema 校验（覆盖 type / required / enum / properties / items / allOf / 本地 $ref，循环引用安全终止）。 无法解析的引用或范围外约束标为无法判定、不计风险；旧版拒绝的样本也不计风险。 结果只供本次查看，不改变原审查结论。

🔗 Link 后续调用参数预览（响应实例 → 下一跳）

选择旧 / 新版与源操作（HTTP 方法 + 路径模板），提交一次响应实例（状态码、JSON 响应体、响应头）； 响应按精确码 → 范围码（1XX…5XX）→ default 匹配，逐条 Link 显示指针、目标方法 / 路径 （唯一 operationId 或本地 operationRef）与每个参数的取值（路径级 + 操作级合并，操作级覆盖）。 值支持 JSON 常量、$response.body#/JSONPointer（解码 ~0/~1）、 $response.header.名称（头名忽略大小写）；null 算已提供，其余表达式报不支持； 外部引用 / 歧义 / 未知参数 / 缺少必填值逐条报错。只预览、不发请求、不入库、不改变审查结论。

语义兼容性规则

判定按两个方向独立进行：请求方向关注"客户端原本合法发送的内容是否被收紧"； 响应方向关注"客户端原本可能收到的承诺是否被改变"。因此同一类 schema 变化在两个方向上结论可能相反。
